## The pipeline

```
python tools/meshy_adopt.py <export.glb> assets/models/creatures/<name>.glb --patch-import
godot --headless --path . --import
godot --headless --path . --script res://tools/meshy_rig_probe.gd -- --asset res://...
```

`meshy_adopt.py` caps textures at 1024, normalises the clip name, derives the BoneMap from the
rig, resets `root_scale`, and patches the `.import`. Flags: `--root-scale` for a deliberate scale
correction, `--strip-animations` when Meshy's own clip is deformed.

`meshy_rig_probe.gd` is a **gate, not a spot check** — it fails the build if the retarget did not
run. Run it on every adopted model.

⚠️ `meshy_download_model`'s `save_to` does **not** write a file. Read `running_glb_url` out of the
response and `curl` it.

## Traps already paid for — do not rediscover these

1. **Meshy's bone names are unreliable.** The spine is named inverted
   (`Hips → Spine02 → Spine01 → Spine`, so `Spine` is the *top* joint), and on `npc_innkeeper` the
   labels sat on the wrong joints entirely. `meshy_adopt.py` derives the map by walking the
   hierarchy to the shoulder-carrying joint. Do not hand-write a BoneMap.
2. **The `.import` `_subresources` key is `PATH:Armature/Skeleton3D`** — it starts at the scene
   root's *first child*, not the root. Wrong key = retarget silently does not run, the actor
   T-poses, no log, no error.
3. **A replacement inherits its predecessor's `.import`.** `npc_woman_dress` carried
   `root_scale 0.384` and would have imported at 38%.
4. **A sound mesh can ship on a broken rig.** `npc_innkeeper`'s own clip flattened its head into a
   slab while the bind pose was perfect. Render the bind pose before concluding a model is bad.
5. Models face **+Z**; the factories already rotate 180°. No change needed.

## Findings from the Group A/B sessions (2026-09-02)

Four traps that cost real time or credits, none of them in the list above.

1. **`meshy_adopt.py --patch-import` needs the `.import` to already exist.** A brand-new asset needs
   adopt → `--import` → adopt again. Only `enm_cultist` hit this; every other adoption replaced a
   file that already had a sidecar.
2. **Meshy's rigged rest pose is A-pose, not T-pose.** A torso slice taken between 45% and 70% of
   height catches the forearms and over-reports the capsule radius by up to 2×. Measure the body
   core, or read depth (Y) rather than width (X), which the arms do not contaminate.
3. **The rigging REST endpoint puts `status` at the TOP level and the URLs under `result`.**
   Collapsing to `result` first silently loses `status`, and a poll loop keyed on it never
   terminates. `GET /openapi/v1/rigging/<id>` → `status`, `result.basic_animations.running_glb_url`.
4. **Godot's `detect_3d` pass rewrites a texture `.import` after the first 3D use**, flipping
   `compress/mode` 0 → 2. Adopt, import, *then* commit — or the texture ships uncompressed in VRAM.
   The shipped convention is `compress/mode=2` with `detect_3d/compress_to=0` (`3e38dfa`).

⚠️ **The Godot MCP tools are not reachable from a session that started before the server was up.**
`.mcp.json` is read once at Claude Code startup, so `mcp__ai-game-developer__*` simply does not
exist for the rest of that session even after the editor comes up. The fallback works:
`godot-cli run-tool <name> . --url http://localhost:23630 --input '{...}'`, and `godot-cli status .`
confirms both halves are live. Blender covers the visual QA the procedure above specifies, so this
never blocked the wave.


## Findings from the Group C session (2026-09-02)

1. **`meshy_rig` refuses quadrupeds with a 422 and charges nothing.** "Pose estimation failed,
   please provide a valid model". It is a rejection at the input, not a bad rig you can inspect —
   so the cost of proving a non-humanoid group is unmigratable is 18 credits (image + mesh), not 23.
2. **Meshy's `image_to_3d` returns a mesh normalised to a unit box, not to metres.** The wolf came
   back X 0.291 / Y 0.961 / Z 1.000 with the longest side exactly 1.0. The Group A/B
   "`height_meters` under-delivers" finding is about the *rig* step, which is where the real-world
   scale is applied — an unrigged mesh has no scale at all, so `--root-scale` is not optional for
   any mesh-only adoption.
3. **`smart-topology` at 3.5k tris terraces fur.** The wolf's neck ruff came back as visible
   stair-steps. Budget more tris for a furred silhouette, or accept it.
4. ⚠️ **Two of the three Godot MCP screenshot tools are unusable for model QA, and both fail
   silently.** `screenshot-isolated` returns a flat 1891-byte fill of the background colour for
   every skinned model tried (target the node, its `RootNode`, or the `Skeleton3D` — same blank).
   `screenshot-camera` **ignores transform changes made through `node-modify`**: three different
   camera positions returned a byte-identical PNG, so a camera you never actually moved renders a
   plausible-looking image from the origin, which reads as a working QA pass. **Only
   `screenshot-viewport` is live.** The rig that works is: `node-create` with `instanceScenePath`,
   then rotate the *model* with `node-modify` and capture `screenshot-viewport` per rotation.
5. **`node-modify` needs C# PascalCase property names** — `Position`, `RotationDegrees`, and
   `X`/`Y`/`Z` inside a `Vector3`. The Godot snake_case names (`position`, `rotation_degrees`, `x`)
   are rejected, but the tool still returns `"status": "success"` with the rejection buried in a
   nested `result` array, so an unchecked call looks like it worked.
6. **Godot will not import from `reports/`** — it carries a `.gdignore`, as does `assets/library/`.
   Stage a QA model under `assets/models/` and delete it, its `.import`, and the `_0.jpg` +
   `_0.jpg.import` the importer extracts alongside it.
